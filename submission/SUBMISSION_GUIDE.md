# Team Submission Guide

## Step 1 — Choose a Team Name

Example:

`Grid Insight Lab`

Repository-safe name:

`grid-insight-lab`

## Step 2 — Create One Team Repository

```text
MTL-DA-003-grid-insight-lab
```

One repository per team.

## Step 3 — Add Team Members

Each member should use their own GitHub account.

Do not share one login.

## Step 4 — Add Mettelo Review Access

If the repo is private, add the designated Mettelo reviewer GitHub account.

## Step 5 — Build the Mandatory Structure

Follow `TEAM_REPOSITORY_STANDARD.md`.

## Step 6 — Work Through GitHub

Use:
- issues;
- branches;
- commits;
- pull requests;
- reviews;
- documentation.

Do not wait until the final week to upload all work.

## Step 7 — Complete FINAL_SUBMISSION.md

Create:

```text
submission/FINAL_SUBMISSION.md
```

It must contain:
- submission details;
- repository URL;
- final branch;
- final tag/release;
- links to D1–D11;
- dashboard access;
- key findings;
- recommendations;
- limitations;
- contribution evidence;
- team declaration.

## Step 8 — Final QA

Confirm:
- [ ] repository name follows the standard;
- [ ] Mettelo reviewer has access;
- [ ] README is complete;
- [ ] raw-data acquisition instructions work;
- [ ] code is reproducible;
- [ ] all D1–D11 deliverables are present;
- [ ] dashboard link works;
- [ ] CONTRIBUTIONS.md is complete;
- [ ] FINAL_SUBMISSION.md is complete;
- [ ] no secrets are committed;
- [ ] large raw files are not committed;
- [ ] source dataset is attributed.

## Step 9 — Submit the Repository URL

The official submission is the team's GitHub repository URL.

Do not submit project files by email.

## Step 10 — Freeze the Submitted Version

Create a tag or release:

```text
v1.0-mettelo-submission
```

Mettelo will review the tagged version unless otherwise agreed.
